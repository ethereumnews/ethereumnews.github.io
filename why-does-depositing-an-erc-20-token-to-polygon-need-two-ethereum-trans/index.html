Why does depositing an ERC-20 token to Polygon need two Ethereum transactions?

Depositing an ERC-20 token to Polygon takes two Ethereum transactions because approval grants the predicate permission, then the deposit locks tokens for Polygon PoS.

By Web3 Hub NewsroomNov 25, 2026 · 06:51 UTC2 min read

A 500 USDC deposit to Polygon PoS usually takes two Ethereum transactions: one approves the bridge predicate to use the USDC, and the next deposits it. ERC-20 tokens require that approval because a contract can move your tokens only within the allowance you grant it.

In the first transaction, your wallet calls USDC’s approve function and sets an allowance of 500 USDC for the predicate contract. That transaction changes the token’s allowance on Ethereum; it does not send USDC to the bridge.

What happens in a 500 USDC deposit?

The second transaction calls depositFor on RootChainManager, which routes the deposit through ERC20Predicate. The predicate uses transferFrom to pull and lock the 500 USDC on Ethereum, then state sync carries the deposit information so Polygon PoS credits the mapped token there.

The Polygon bridge is the route that connects this Ethereum lock to the Polygon PoS credit. The two prompts reflect two separate actions: setting token permission, then submitting the deposit that uses it.

If you approve 500 USDC and stop there, your tokens have not left Ethereum. Reopen Polygon Portal and the allowance is already set, so the next prompt should be only for the deposit; the USDC moves when that transaction completes.

Can the next deposit skip approval?

An existing allowance can let a later deposit skip the approval transaction. With an exact-amount approval, the 500 USDC allowance is used for that deposit, so you need to approve again next time.

A larger allowance can cover later deposits and avoid another approval while enough allowance remains. It also leaves the predicate with standing permission to move tokens up to that allowance, so choose an amount that fits your use.

Native ETH deposits use a different route: Polygon’s depositEtherFor function handles the deposit in one Ethereum transaction, without an ERC-20 approval step.
