Three checks to make before a bridge transfer is complete

A source-chain transaction marked successful does not prove a bridge transfer is complete; check the network, transaction details and destination status before acting.

By Web3 Hub NewsroomOct 22, 2026 · 18:44 UTC3 min read

A bridge transfer is not complete just because its source-chain transaction is marked successful; check the network, transaction details and destination status before treating the funds as available. The source transaction starts the process, while bridge contracts and network messaging handle what happens next.

Is the transaction on the right source chain?

Confirm that the transaction hash belongs to the network you intended to send from. A wallet can switch networks without making the destination obvious, and a transaction on the wrong chain will not trigger the transfer you expect.

Open the hash in that chain’s block explorer and compare the sender, recipient contract, token and amount with the details shown in your wallet. For an ETH transfer from Ethereum to Polygon PoS, the guide to moving ETH through Polygon Bridge covers the steps in more detail. A successful status only confirms that the source-chain transaction was accepted; it does not, by itself, confirm delivery on Polygon.

Does the source transaction have the required confirmations?

Check the explorer’s confirmation or finality status before relying on a transfer that is still pending. A pending transaction has not been included in a block; a confirmed transaction has been included, but the bridge may still need to process it.

There is no single confirmation count that applies to every bridge. The bridge’s status page or instructions determine when it considers the source transaction ready, and network congestion can affect how long that takes. If the transaction is pending, wait for it to settle before retrying, so you do not accidentally submit a second transfer.

Has the bridge credited the destination chain?

Check the bridge’s transfer record and the destination chain before assuming the asset has arrived. For an Ethereum-to-Polygon PoS deposit, the source transaction locks the asset on Ethereum; a corresponding amount is then made available on Polygon through the bridge’s deposit process.

  • Match the source transaction hash and transfer amount.
  • Confirm the destination network and recipient address.
  • Check the destination wallet or explorer for the received asset.
  • Read the bridge status if the source is confirmed but the destination is pending.

A confirmed source transaction and a completed bridge transfer are separate milestones. For withdrawals from Polygon PoS to Ethereum, the bridge uses a different process: Polygon’s support documentation says the asset is burned on Polygon and unlocked on Ethereum, and a checkpoint is required before the final claim. Check the bridge’s current status for the next step; treat the transfer as complete only when the destination balance or transaction record confirms receipt.
